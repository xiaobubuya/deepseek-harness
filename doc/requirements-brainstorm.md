# AI Agent Server 需求文档（脑暴版）

## 1. 项目愿景

**核心问题**：PhotoCraft CLI 功能强大但使用门槛高，普通用户难以直接使用。

**解决方案**：通过自然语言对话驱动 CLI，让用户用"说话"的方式编辑照片。

**终极目标**：
- 用户上传图片 → 用自然语言描述需求 → AI 自动执行编辑 → 实时看到效果
- 集成到 muyaya.world/photocraft/，无缝体验

## 2. 用户需求分析

### 2.1 目标用户群体

| 用户类型 | 需求特点 | 优先级 |
|----------|----------|--------|
| 普通用户 | 不懂命令行，只会说话 | ⭐⭐⭐⭐⭐ |
| 进阶用户 | 知道想做什么，但懒得记命令 | ⭐⭐⭐⭐ |
| 专业用户 | 需要批量处理，追求效率 | ⭐⭐⭐ |

### 2.2 用户场景

```
场景1：简单调色
用户："这张照片太暗了，亮一点"
期望：自动调整亮度，可能加上对比度

场景2：风格转换
用户："我想让这张照片看起来像电影海报"
期望：多步骤操作（色调、对比度、锐化等）

场景3：批量处理
用户："帮我把这10张照片都调成暖色调"
期望：批量执行，节省时间

场景4：探索式编辑
用户："这张照片怎么让它看起来更专业？"
期望：AI 分析后给出建议并执行
```

### 2.3 用户痛点

| 痛点 | 描述 | 解决方向 |
|------|------|----------|
| 学习成本高 | 命令行参数太多记不住 | 自然语言输入 |
| 反馈慢 | 执行完才知道结果 | 实时进度反馈 |
| 批量麻烦 | 一张张处理太慢 | 批量处理支持 |
| 效果不确定 | 不知道改完什么样 | 实时预览/对比 |

## 5. 技术选型（脑暴）

### 5.1 后端框架选项

| 方案 | 优点 | 缺点 | 评分 |
|------|------|------|------|
| Express + TypeScript | 轻量、生态好 | 需自行搭建 | ⭐⭐⭐⭐⭐ |
| FastAPI (Python) | 类型安全、文档好 | 需要 Python 环境 | ⭐⭐⭐⭐ |
| Next.js API Routes | 全栈一体 | 较重 | ⭐⭐⭐ |
| Koa + TypeScript | 比 Express 灵活 | 生态较小 | ⭐⭐⭐⭐ |

**选择**：Express + TypeScript（轻量、成熟、TypeScript 支持好）

### 5.2 WebSocket 方案

| 方案 | 优点 | 缺点 | 评分 |
|------|------|------|------|
| ws | 轻量、无依赖 | 需自行处理心跳 | ⭐⭐⭐⭐⭐ |
| socket.io | 功能全 | 较重 | ⭐⭐⭐⭐ |
| ws + socket.io 混合 | 灵活 | 复杂 | ⭐⭐⭐ |

**选择**：ws（轻量、够用）

### 5.3 LLM 模型选项

| 模型 | 优点 | 缺点 | 评分 |
|------|------|------|------|
| 通义千问 (qwen) | 中文好、便宜 | 需要 API Key | ⭐⭐⭐⭐⭐ |
| DeepSeek | 推理强 | 价格稍高 | ⭐⭐⭐⭐ |
| GPT-4 | 效果好 | 贵、需要代理 | ⭐⭐⭐ |
| 本地模型 | 免费 | 需要 GPU | ⭐⭐ |

**选择**：通义千问 sensenova-6.8-flash-lite（中文好、便宜）

### 5.4 部署方案

| 方案 | 优点 | 缺点 | 评分 |
|------|------|------|------|
| Node.js + pm2 | 简单、稳定 | 单机 | ⭐⭐⭐⭐⭐ |
| Docker + Docker Compose | 可移植 | 学习成本 | ⭐⭐⭐⭐ |
| 云函数 | 自动伸缩 | 冷启动 | ⭐⭐⭐ |
| Kubernetes | 高可用 | 复杂 | ⭐⭐ |

**选择**：Node.js + pm2（简单、够用）

## 6. API 设计（脑暴）

### 6.1 RESTful API

```
POST /api/upload          # 上传图片
GET  /api/images          # 图片列表
GET  /api/images/:id      # 获取图片
POST /api/chat            # 发送编辑指令
GET  /api/health          # 健康检查
GET  /api/status/:taskId  # 任务状态
```

### 6.2 WebSocket 消息

```javascript
// 客户端 → 服务器
{ type: "chat", message: "调亮一点", imageId: "xxx" }
{ type: "cancel", taskId: "xxx" }
{ type: "ping" }

// 服务器 → 客户端
{ type: "ack", taskId: "xxx" }
{ type: "thinking", thought: "正在分析..." }
{ type: "command", command: "color.brightness", params: { value: 30 } }
{ type: "progress", step: 1, total: 3, message: "调整亮度" }
{ type: "log", level: "info", message: "..." }
{ type: "done", resultUrl: "/processed/xxx.jpg" }
{ type: "error", code: "EXECUTION_ERROR", message: "..." }
```

### 6.3 数据模型

```typescript
// 图片
interface Image {
  id: string;
  filename: string;
  originalName: string;
  size: number;
  createdAt: Date;
  processedAt?: Date;
  status: 'uploaded' | 'processing' | 'done' | 'error';
}

// 编辑任务
interface EditTask {
  id: string;
  imageId: string;
  message: string;
  commands: Command[];
  status: 'pending' | 'running' | 'done' | 'error';
  createdAt: Date;
  completedAt?: Date;
  resultUrl?: string;
  error?: string;
}

// CLI 命令
interface Command {
  cmd: string;
  params: Record<string, unknown>;
}
```
